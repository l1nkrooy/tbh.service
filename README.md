# Hero Service — сайт услуг прокачки для Task Bar Hero

Премиальный сайт-конфигуратор услуг прокачки для игры Task Bar Hero. Next.js
(App Router) + TypeScript + Tailwind CSS v4 + Framer Motion + GSAP + Lenis +
Supabase.

Языки интерфейса: русский и английский, с автоматическим определением языка
браузера и запоминанием выбора.

## Технологический стек

| Слой | Технология |
|---|---|
| Фреймворк | Next.js 16 (App Router, Turbopack) |
| Язык | TypeScript (строгий режим) |
| Стили | Tailwind CSS v4 (CSS-first конфиг через `@theme`) |
| Анимации | Framer Motion, GSAP + ScrollTrigger |
| Плавный скролл | Lenis |
| Состояние корзины | Zustand (с персистентностью в localStorage) |
| База данных | Supabase (PostgreSQL) |
| Валидация форм | React Hook Form + Zod |
| Генерация PNG заказа | html-to-image |
| Иконки | lucide-react |

Вся прокачка/доступ к Steam-аккаунту описана только как **юридический и
маркетинговый текст** на сайте (FAQ, пользовательское соглашение) — сам сайт
не содержит и не должен содержать кода, который реально логинится в Steam.
Это сайт-витрина и приём заказов; выполнение услуги происходит вручную
командой сервиса после связи в Discord/FunPay.

## Быстрый старт локально

### Требования

- Node.js 20 или новее
- npm 10 или новее
- Аккаунт Supabase (бесплатного тарифа достаточно)

### Шаги

```bash
# 1. Установите зависимости
npm install

# 2. Скопируйте файл окружения и заполните его
cp .env.example .env.local
# откройте .env.local и заполните значения — см. раздел "Переменные окружения"

# 3. Запустите дев-сервер
npm run dev
```

Сайт будет доступен на `http://localhost:3000`.

> **Важно:** сборка скачивает шрифты (Press Start 2P, JetBrains
> Mono) с Google Fonts во время `next build`/`next dev`. Убедитесь, что у
> вашей машины/CI есть доступ к `fonts.googleapis.com` и `fonts.gstatic.com`.

## Настройка Supabase с нуля

Эта секция написана для тех, кто никогда не работал с Supabase.

### Шаг 1 — создать проект

1. Зайдите на [supabase.com](https://supabase.com) и зарегистрируйтесь.
2. Нажмите **New Project**.
3. Укажите имя проекта (например `hero-service`), задайте надёжный
   database password (сохраните его — он нужен только если будете
   подключаться напрямую к Postgres, для обычной работы сайта не требуется)
   и выберите регион ближе к вашим пользователям (например Frankfurt для
   аудитории из СНГ/Европы).
4. Подождите 1–2 минуты, пока Supabase развернёт проект.

### Шаг 2 — применить SQL-схему

1. В боковом меню проекта откройте **SQL Editor**.
2. Нажмите **New query**.
3. Откройте файл `supabase/migrations/0001_init.sql` из этого репозитория,
   скопируйте его содержимое целиком.
4. Вставьте в редактор и нажмите **Run** (или `Ctrl+Enter`).
5. Убедитесь, что запрос выполнился без ошибок — в самом низу появится
   "Success. No rows returned" или похожее сообщение.

Это создаст две таблицы (`orders`, `reviews`) с политиками безопасности
(Row Level Security) и добавит несколько демонстрационных отзывов.

> Если вы уже разворачивали этот проект ранее и у вас в Supabase создана
> таблица `orders` со старой схемой (без способа оплаты DonationAlerts),
> дополнительно выполните `supabase/migrations/0002_add_donationalerts.sql`
> тем же способом. Для нового проекта с нуля это не требуется — всё уже
> учтено в `0001_init.sql`.

### Шаг 3 — получить ключи API

1. В боковом меню откройте **Project Settings → API**.
2. Скопируйте:
   - **Project URL** → это значение для `NEXT_PUBLIC_SUPABASE_URL`
   - **anon public key** → это значение для `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **service_role key** (раскройте секцию "Project API keys", он скрыт по
     умолчанию) → это значение для `SUPABASE_SERVICE_ROLE_KEY`

> ⚠️ **`service_role` ключ даёт полный доступ к базе данных, минуя все
> политики безопасности.** Никогда не публикуйте его, не добавляйте в
> клиентский код и не используйте с префиксом `NEXT_PUBLIC_`. В этом
> проекте он используется только внутри `src/app/api/**` (серверный код).

### Шаг 4 — (опционально) проверить таблицы

В боковом меню откройте **Table Editor** — там должны появиться таблицы
`orders` и `reviews`. В `reviews` уже будут 4 демонстрационных отзыва.

## Переменные окружения

Все переменные описаны в файле `.env.example`. Скопируйте файл в
`.env.local` и заполните:

| Переменная | Где взять | Обязательна |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API | Да |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → Project Settings → API | Да |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API | Да |
| `NEXT_PUBLIC_SITE_URL` | Ваш домен (для SEO/sitemap) | Нет, есть дефолт |
| `NEXT_PUBLIC_DISCORD_INVITE_URL` | Ссылка-приглашение на ваш Discord-сервер | Да, для реальной работы кнопок |
| `NEXT_PUBLIC_FUNPAY_URL` | Ссылка на ваш профиль/лот на FunPay | Да, для реальной работы кнопок |

## Деплой на Vercel

### Вариант А — через сайт Vercel (проще)

1. Загрузите этот проект в свой репозиторий на GitHub (см. ниже).
2. Зайдите на [vercel.com](https://vercel.com), нажмите **Add New → Project**.
3. Выберите ваш репозиторий.
4. В разделе **Environment Variables** добавьте все переменные из
   `.env.example` с вашими реальными значениями (см. таблицу выше).
5. Нажмите **Deploy**.
6. После деплоя обновите `NEXT_PUBLIC_SITE_URL` на реальный домен Vercel
   (или ваш кастомный домен) и переразверните проект (Redeploy).

### Как загрузить проект на GitHub (если ещё не сделано)

```bash
cd taskbarhero
git init
git add .
git commit -m "Initial commit: Hero Service"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
git push -u origin main
```

### Вариант Б — через Vercel CLI

```bash
npm install -g vercel
vercel login
vercel        # деплой preview
vercel --prod # деплой в продакшен
```

CLI спросит про переменные окружения интерактивно, либо добавьте их заранее
через `vercel env add`.

### Подключение собственного домена

В панели Vercel откройте проект → **Settings → Domains** → добавьте ваш
домен и следуйте инструкциям по настройке DNS-записей у вашего регистратора.

## Конфигурация цен и контента

Вся бизнес-логика цен находится в одном файле: `src/lib/pricing/calculator.ts`.
Там задокументированы все формулы — прокачка персонажей, Куба, золота, буста
по этажам/сложностям. Чтобы изменить цены:

- **Тиры золота и паки** — редактируйте `src/data/packs.ts`.
- **Базовые цены за уровень** — константы в начале каждой секции
  `calculator.ts` (например `CHAR_LEVEL_BASE_PRICE`, `CUBE_LEVEL_BASE_PRICE`).
- **Множители сложности буста** — `DIFFICULTY_MULTIPLIER` в `calculator.ts`.
- **Тексты FAQ и соглашения** — `src/data/faq.ts` и `src/data/terms.ts`.
- **Все остальные тексты интерфейса (RU/EN)** — единый файл
  `src/lib/i18n/dictionaries.ts`.

## Известные ограничения и рекомендации

- **Оплата на сайте не принимается напрямую** — это сознательное решение,
  соответствующее техническому заданию (владелец сервиса не зарегистрирован
  как ИП/самозанятый). Оплата согласовывается в Discord или на FunPay после
  оформления заказа на сайте.
- **Модерация отзывов** — новые отзывы сохраняются с `is_published = false`
  и не показываются на сайте, пока вы не измените это поле на `true` через
  Supabase Table Editor (это сделано специально, чтобы избежать спама/
  накрутки отзывов без вашего контроля).
- **Личного кабинета с регистрацией нет** — согласно техническому заданию,
  сайт работает без регистрации. Просмотр оформленного заказа доступен по
  прямой ссылке `/order/[id]`, которую получает покупатель сразу после
  оформления.
- **Иллюстрации персонажей загружаются вручную**: положите 6 PNG-файлов с
  прозрачным фоном в `public/images/characters/` с именами `knight.png`,
  `priest.png`, `sorcerer.png`, `ranger.png`, `hunter.png`, `slayer.png` —
  страница «Прокачка персонажей» подхватит их автоматически, без правок
  кода. Пока файлов нет, на их месте отображается стандартная иконка
  "битой картинки" браузера — это не ошибка, просто заглушка до загрузки.
  Пути на иллюстрации заданы в `src/data/characters.ts`.
- **Изображения** оптимизируются через встроенный Next.js Image Optimization
  (включена поддержка SVG в `next.config.ts`).
